## 設計の柱

### 1. 何であるかを知らない

入力は「大きさを持つもの」と「つながり」だけ。クラスでも、すごろくのマスでも、麻雀卓の席でも、ウィンドウでも同じに扱う。

これは制約ではなく**梃子**で、同じ 300 行が可視化にもゲームにも効く。相手の語彙（ZIR のノード種別、麻雀の席、駅）を吸収するのは `integration/` の仕事で、コアは知らない。

### 2. 描画しない

DOM も canvas も three.js も import しない。返すのは座標と測定値だけ。

理由は 2 つ。**テストがブラウザ無しで書ける**こと（88 本が `node` だけで走る）と、**同じ配置を SVG にも three.js にも渡せる**こと。3D のラベル重なりを、画面へ投影してから 2D の `placeLabels` に渡せるのはこの分離のおかげ。

### 3. 決定論的

乱数を使うのは `rng` と `relationMap` だけで、どちらも `seed` を取る。同じ入力からは必ず同じ座標が出る。

図が毎回動くと、人は「何が変わったのか」を読めない（メンタルマップが壊れる）。差分を見せるツールでは致命的。

### 4. 依存ゼロ

`node test.mjs` だけで全部走る。ゲーム側（netmahg は外部依存パッケージがゼロ）に持ち込んでも汚さない。

### 5. 測定のメッセージには実測値・閾値・直し方を必ず入れる

```
H102 station-042 のラベル「新千歳空港」が 12.3px はみ出す
     （文字 88px > 使える幅 76px）— fitText() を通すか図形を広げる
```

読むのは人か LLM で、**メッセージだけを見て直せないと意味がない**。この考え方は [archify](https://github.com/tt-a1i/archify) の visual-check から借りた。

## 配置アルゴリズム

### `pack` — 入れ子の円詰め

葉から親へ向かって畳む。

1. 子を先に詰めて、その外接半径から自分の半径を決める（再帰）
2. 大きい順に、**既存の 2 円それぞれに外接する点**を候補にする（`tangentPoints`）
3. 候補のうち、他と重ならず**中心に最も近い**ものを選ぶ
4. どこにも置けなければ、外周へ逃がす（角度は `seed` から決まるので決定論的）

d3-hierarchy の front-chain 法を単純化したもの。厳密な最密充填ではないが、**依存ゼロで決定論的**で、階層ごとに `padding(depth)` を変えられる。

> 実装の落とし穴: 最初、再帰が**共有の Map を返していた**。子を親の座標へ平行移動する処理がすでに置いた全ノードに掛かり、`parent` も全部同じ id で上書きされた。局所の Map を返して親が畳む形に直した。

### `tree` — 階層

Reingold-Tilford の簡易版。葉に左から順に x を振り、親は子の中央に置く。横断辺（兄弟間の依存）は見ていないので、依存の向きを読ませたいなら Sugiyama が要る（[まだ無いもの](#まだ無いもの)）。

### `treemap` — squarified

面積を値に比例させながら、**縦横比が 1 に近くなるよう**行を切る。

1. 残りの領域の長辺方向に行を作る
2. 次の要素を足したときの「最悪の縦横比」が悪化する直前で行を確定（`worst`）
3. 残りの領域を削って繰り返す

`children` があれば領域を再帰的に割る。CodeCity の街区も、ダッシュボードのタイルもこれ。

### `relax` — 重なり解消

ゲームの broad phase と同じ。重なった対を、中心を結ぶ向きに押し離すのを繰り返す。

- `axis` … 動かす向きを縛る（`'x'` / `'y'` / `'xy'`）
- `maxMove` … 元位置からの距離を縛る（メンタルマップを保つ）
- `bounds` … **毎反復で領域内へ引き戻す**
- `grid` … 最後に格子へ載せ直す
- `pinned` … 動かさない id

> **`bounds` が要る理由**: 領域の外へ押し出せば重なりは必ず消える。だがそれは解決ではない。netmahg で手牌を押し離したら重なりは 0 になったが幅が 543px に再拡大し、355px の画面に入らなくなった。入りきらないなら**重なったまま残し、`measure` が H110 で報告する**のが正しい。

> 完全に同じ位置にあると、押し離す向きが決まらない（差分ベクトルがゼロ）。`id` から決まる角度へ逃がす。乱数ではないので決定論的。

### `grid` — 順序を保つ並べ

手牌・ツールバー・タブは、**押し離しでは並べられない**（順序が壊れる）。左から順に置き、`cols` か `bounds.w` で折り返す。

**入りきらない量は `overflow` で返すだけで、勝手に縮めない。** 縮めるか、スクロールにするか、数を減らすかは呼ぶ側が決めること。

### `placeLabels` — ラベルの置き場所

図形の中に入るなら中、入らないなら周囲 8 方向。置いた矩形を `taken` に積み、重なる候補は飛ばす。どこにも置けなければ `hidden: true`。

> **最大の欠陥はここにあった。** 内に入るかを「切り詰めた**後**の文字」で判定していたため、`fitText` が返した「…」が常に内に収まり、**外周 8 方向を一度も試さなかった**。tetsugo の 616 駅が全部「…」になり、しかも `measure` はそれを「問題なし」と報告した。
>
> 内外は**切り詰める前の全長**で決めるもの。直した結果、inside 6 / outside 610 / 衝突 0 組（tetsugo 自前の貪欲法の 1 組より良い）。

`priority` で置く順を変えられる（重要なラベルが先に場所を取る）。`prefer: 'outside'` / `dirOrder` で方針を差し替えられる。

### `fitText` — 幅に収める

幅を超える手前まで文字を積み、超えたら**末尾を削って「…」のぶんの幅を空ける**。「…」すら入らないなら空を返す（1 文字だけ出しても意味がないので）。

> 元は省略記号を幅計算の**外**で足しており、切り詰めた結果が幅を 1 文字ぶん超えていた。zumen の 174 リポジトリで 3,558 件のはみ出しの原因。

全角は半角の 1.75 倍で数える。等幅でない前提の粗い見積りなので、正確な幅が要るなら DOM 実測が要る（[まだ無いもの](#まだ無いもの)）。

## 測定の考え方

### なぜ測るのか

座標を出す道具は世に多い。足りないのは**出した配置が読めるかを測る**道具で、そこが実際に事故を生む。

「データは正しいが図が読めない」という欠陥は、**中間表現（IR）の検証では絶対に捕まらない**。配置と同じ場所で測るしかない。

### 何を測っているか

幾何で測れることだけ。「美しいか」は測らない。

| 種類 | 規則 |
|---|---|
| 重なり | H101（図形・外置きラベル）、V101（立体） |
| 文字 | H102 はみ出し、H103 小ささ、H111 切り詰め、V104 距離で読めない |
| 線 | H104 交差数、H105 貫通、H107 交差角、H108 ラベル横切り |
| 全体 | H106 縦横比、H109 間引きすぎ、H110 領域外 |
| 3D | V102 通行、V103 遮蔽、V105 ラベルの場所、V107 高さの落差 |

全一覧は [測定規則](./rules.ja.md)。

### 誤検出を避ける工夫

測定器が嘘をつくと、**無いバグを追いかけて実物を壊す**。実際に踏んだ 3 つ。

1. **入れ子を重なりと数えない** — 親の中に子がいるのは正しい姿。`parent` が同じ図形どうしだけを比べる
2. **描画側の条件をそのまま写す** — zumen ではラベルを `r*k > 34` で隠していた。それを知らずに測ると、隠れているラベルを「読めない」と報告する
3. **正しい用途を責めない** — 一列に並べてスクロールさせる手牌に「縦横比 522:1」と警告した。`scrollable: true` で黙る

### H109 が要る理由

**辺を捨てれば交差も貫通も減るので、指標だけは良くなる。** 全部消せば満点になってしまう。捨てた重みを `totalEdgeWeight` で渡してもらい、「見えている割合」で歯止めをかける。

## 3D で何が変わるか

2D の指標をそのまま持ち込んでも測れないものが 3 つある。**どれも視点を与えないと測れない**ので、`measure3` は camera を取る。

1. **遮蔽** — 手前の物が奥を隠す。「置いてあるのに見えない」は 2D に無い
2. **通行** — 人が歩くなら、隙間が狭いと通れない（`walkWidth`）
3. **距離による可読性** — ラベルの大きさは距離で決まる

### `project` — 透視投影

three.js を使わず、視線基底（forward / right / up）を作って視点座標へ移し、焦点距離 `f = (H/2) / tan(fov/2)` で割る。返り値の `scale` が「1 world unit が何 px か」で、これでラベルの実効サイズが決まる。

### `visibleFrom` — 見えるものだけ

視錐台の外を落とし、手前から順に見て**完全に覆われたもの**を落とす。遮蔽はバウンディング球を画面へ投影した円で近似する。正確さより速さで、迷ったら「見える」側へ倒す（ゲームの階層 Z カリングと同じ発想）。

### `semanticLod` — 意味の LOD

距離ではなく**画面に占める大きさ**で、どの深さまで開くかを決める。遠景は repository、寄ると component、さらに寄ると unit。

ヒステリシス（開いているものは閉じにくくする）を入れて、境界での点滅を防ぐ。Unreal の HLOD を「形状の簡略化」ではなく「意味の粒度」に読み替えたもの。

### ラベルは 2D に委ねる

3D のラベル重なりは、**画面へ投影してしまえば 2D の問題**。同じ `placeLabels` / `measure` に渡す。同じ問題には同じ道具を使う。

## 実地で見つかった欠陥

このエンジンが良くなったのは、全部**実際のプロダクトに当てて批判されたから**。

| 相手 | 見つかったもの |
|---|---|
| **zumen**（174 リポジトリの可視化） | `fitText` が省略記号を幅の外で足していた／ラベルの表示可否を半径で判断していて、小さい図形は下限 4px で頭打ちになっていた（指摘 8,842 → 0） |
| **tetsugo**（すごろく 3,583 マス） | `placeLabels` が切り詰めた「…」で内外を判定していた／`alongPath` が格子・斜め禁止・区間マス数を表現できなかった／`measure` が外置きラベルを見られなかった |
| **netmahg**（麻雀） | `integration/` が配布物に無かった／完全同位置で `relax` が分離しなかった／画面外へ押し出す解を成功扱いしていた／`roundTable` の座順が逆だった |
| **codex のレビュー** | 円と矩形が混在すると重なりを見落としていた（同心の r=10 円と 20×20 矩形を「重なり 0」と回答）／`alongPath` の終点が届かない |

とくに tetsugo の指摘は痛烈だった。

> README が「zumen で見つけた」と誇っている 2 つの欠陥と**同じ型のバグが placeLabels 自身に入っている**

他人の図を検査する道具が、自分の配置で同じ間違いをしていた。**上の欠陥は全部テストで固定してある。**

## まだ無いもの

**線の引き方**。今は「その線は読めない」と言うだけで、どう引けばいいかは返さない。zumen で `H105`（辺が図形を貫く）が 127 件出ているが、解く手段が無い。

Graphviz が偉いのは**配置と線を同時に解いている**ところで、後から線だけ引くと通り道が残っていない。だから別ライブラリに出さず、ここに入れるべきだと考えている。

| 入れたいもの | 効くところ |
|---|---|
| `layered(nodes, edges)` — Sugiyama。層に割り、交差が減るよう順序を決める | 依存の向きが読める。`tree` は横断辺を見ていない |
| `route(edges, obstacles)` — 直交ルーティング。折れ点の列を返す | H105 が解ける |
| `anchorPorts(shape, edges)` — 端点をどの辺のどこから出すか | H107（浅い交差角）が構造的に減る |
| `bundle(edges, hierarchy)` — 階層エッジバンドリング | 本数の見かけが減る |

ほかに、**DOM を実測しないと分からないもの**（実フォントの幅、テキストの折返し行数、baseline、box model の padding/border）はこのエンジンの外側。粗い見積りで足りるかは用途による。
