# 測定規則

`measure()` / `measure3()` が返す `problems[].code` の一覧。

**メッセージには必ず実測値・閾値・直し方が入る。**読むのが人でも LLM でも、メッセージだけを見て直せなければ意味がないから。

- H = 2D（`measure`）
- V = 3D（`measure3`）

---

## 2D（`measure(shapes, edges, opts)`）

### H101 — 図形が重なっている

同じ `parent` を持つ図形どうしが `gap` 未満に近づいている。`labelBox` を渡した外置きラベル同士も見る。

- **既定の閾値**: `gap = 2`（重なり 0.5px 超で報告）
- **入れ子は重なりではない**。親の中に子がいるのは正しい姿なので、`parent` が同じものだけを比べる。`parent` を渡さなければ全対を比べる
- **円と矩形の混在も正しく測る**（v0.0.3 以降）。円は「幅も高さも 2r の矩形」ではないので、最近点との距離で測る
- 直し方: `relax()` で押し離す、どちらかを小さくする、親の `padding` を広げる

### H102 — ラベルが図形からはみ出す

2 通りある。

1. **1 文字も入らない**（切り詰めても「…」だけ、または空）— 情報がゼロになる
2. 切り詰めた文字がまだ幅を超えている — `fitText()` を通していない経路

- **既定の閾値**: 使える幅 = 円なら `2r - 6`、矩形なら `w - 6`
- `labelBox` を渡した図形は対象外（外置きは、はみ出しようがない）
- 直し方: 図形を広げる、`placeLabels()` で外に出す、その深さでは名前を出さない

### H103 — 文字が読める最小サイズを下回る

- **既定の閾値**: `minFont = 9`（px）
- 直し方: 図形を大きくする、その深さでは出さない

### H104 — 辺の交差が多すぎる

- **既定の閾値**: 全対の 15%。辺が 5 本以上のときだけ見る
- 直し方: 階層レイアウトにする、辺を間引く（ただし H109 を参照）

### H105 — 辺が無関係な図形を貫いている

端点でもその祖先でもない図形を、辺が通り抜けている。

- 直し方: 直交ルーティングにする、図形を動かす
- **現状このエンジンに解く手段が無い**（[まだ無いもの](./internals.ja.md#まだ無いもの)）

### H106 — 縦横比が極端

- **既定の閾値**: 6:1（図形が 4 つ以上のとき）
- **`scrollable: true` を渡すと出さない。** 手牌やツールバーのように「一列に並べてスクロールさせる」のが正しい用途もある
- 直し方: 段組みにする、深さを減らす

### H107 — 交差の角度が浅い

交差の「数」より「角度」が読みやすさを左右する（Purchase らの実験）。直角に近い交差は目で追えるが、浅い交差は線が分岐して見える。

- **既定の閾値**: 20°
- 直し方: 端点をずらす、経路を曲げる

### H108 — 辺がラベルの上を通っている

- 直し方: `placeLabels()` でラベルを逃がす、辺に白フチを付ける

### H109 — 辺を間引きすぎ

**辺を捨てれば交差も貫通も減るので、指標だけは良くなる。** 全部消せば満点になる。それを防ぐ歯止め。

- `opts.totalEdgeWeight`（間引く前の重みの合計）を渡したときだけ見る
- **既定の閾値**: 見えている重みが 50% 未満
- 直し方: 間引きで解いたことにしない

### H110 — 領域からはみ出している

`opts.bounds` を渡したときだけ見る。**押し出して重なりを消す解を成功扱いしない**ための歯止め。

- 直し方: 数を減らす、折り返す

### H111 — ラベルの大半が切り詰められている

1〜2 個なら普通のことだが、過半が「…」付きなら、その深さで名前を出す設計自体が合っていない。

- **既定の閾値**: ラベルが 4 つ以上あって、切り詰め率 50% 超
- 直し方: 図形を大きくする、`placeLabels()` で外に出す、その深さでは名前を出さない

## 3D（`measure3(objects, edges, camera, opts)`）

3D で新しく問題になるのは 3 つで、2D の指標をそのまま持ち込んでも測れない。**どれも視点が要る**ので `camera` を渡すこと（`null` を渡すと V101 / V102 / V107 だけ見る）。

### V101 — 立体が重なっている

H101 の 3D 版。球と直方体の混在も正しく測る（v0.0.3 以降）。

### V102 — 通れない隙間

`opts.walkWidth` を渡したときだけ見る。片方の軸で重なっていて、もう片方の隙間が歩ける幅に満たないなら通り抜けられない。

- 歩けることが前提の街（一人称視点で歩ける等）で効く
- 直し方: 区画の `padding` を広げる

### V103 — 手前の物に完全に隠れている

- **既定の閾値**: 全体の 30%
- 直し方: 視点を上げる、高い建物を外側に置く

### V104 — この距離ではラベルが読めない

ラベルの実効サイズは `worldFont × scale` で決まり、`scale` は距離に反比例する。

- **既定の閾値**: `minFont = 9`（px）
- 直し方: 距離でフェードさせる、寄るまで出さない

### V105 — ラベルが画面上で置き場所を失っている

投影した画面座標で `placeLabels()` を掛け、周囲すべてが埋まっていたもの。

- 直し方: 表示数に上限を設ける、視点を引く

### V106 — ラベルが図形からはみ出す

H102 の 3D 版（投影後の画面座標で測る）。

### V107 — 高さの落差が極端

低い建物が谷に埋もれて見えなくなる。

- **既定の閾値**: 最大が中央値の 40 倍
- 直し方: 高さを対数にする、上限で頭打ちにする

## `metrics`

`problems` が空でも、傾向を見るのに使える数値。

### 2D

| key | 意味 |
|---|---|
| `shapes` / `edges` | 測った数 |
| `overlaps` | 重なっている対の数 |
| `overflow` | はみ出しているラベルの数 |
| `unreadable` | 読める最小を下回るラベルの数 |
| `truncated` | 切り詰められたラベルの数 |
| `outside` | 領域からはみ出した図形の数（`bounds` 指定時） |
| `crossings` / `crossingRatio` | 辺の交差数と、全対に対する割合 |
| `minCrossAngle` / `shallowCrossings` | 最小交差角（度）と、20°未満の交差の数 |
| `pierces` | 無関係な図形を貫いている辺の数 |
| `labelHits` | ラベルの上を通っている辺の数 |
| `aspect` | 縦横比 |
| `visibleEdgeWeightRatio` | 見えている辺の重みの割合（`totalEdgeWeight` 指定時） |
| `edgeLengthCV` | 辺の長さのばらつき（変動係数。大きいほど不揃い） |

### 3D

| key | 意味 |
|---|---|
| `objects` | 測った数 |
| `overlaps` | 重なっている対の数 |
| `narrowGaps` | 通れない隙間の数（`walkWidth` 指定時） |
| `occluded` / `visibleRatio` | 完全に隠れている数と、見えている割合 |
| `unreadableLabels` | この距離では読めないラベルの数 |
| `heightRatio` | 最大の高さ ÷ 中央値 |

## 閾値を変える

すべて `opts` で上書きできる。

```js
measure(shapes, edges, {
  minFont: 11,        // もっと大きい字を要求する
  gap: 4,             // もっと隙間を要求する
  cw: 0.6,            // 文字幅の係数（font に掛ける）
  bounds: { x, y, w, h },
  scrollable: true,   // 一列＋スクロールが正しい用途
  totalEdgeWeight: 1234,
});
```

**閾値に絶対の根拠は無い。** 9px は「日本語が読める下限」の経験則で、20° は交差の実験研究から、15% と 30% と 40 倍は実データを見て決めた。用途に合わせて変えること。
